# Архитектура «для чайников»: Ядро ↔ Плагины ↔ Приложение ↔ База данных

Это руководство объясняет устройство фреймворка `rsgi-wsrpc` простыми словами, на наглядных схемах и аналогиях из реальной жизни.

---

## 1. Большая картина взаимодействия

```text
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │                      КЛИЕНТ (Браузер / Мобилка / Frontend)                  │
 └──────────────────────────────────────┬──────────────────────────────────────┘
                                        │  WebSocket (WSRPC JSON-RPC 2.0)
                                        ▼
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ 1. ЯДРО (rsgi-wsrpc / core) — «Связист и диспетчер»                         │
 │                                                                             │
 │  • Принимает сырые пакеты сети (RSGI / WebSocket).                          │
 │  • Парсит JSON-RPC: {"method": "login.submit", "params": {...}, "id": 1}    │
 │  • Хранит живое WebSocket-соединение (`JsonRpcSession`).                   │
 │  • Ничего НЕ знает про пользователей, пароли, помидоры или агрономию.       │
 │  • Находит зарегистрированный метод в таблице маршрутов и вызывает его.     │
 └──────────────────────┬───────────────────────────────┬──────────────────────┘
                        │                               │
       вызов системных  │                               │ вызов прикладных
       методов (auth)   │                               │ методов (agrita)
                        ▼                               ▼
 ┌──────────────────────────────────────┐  ┌───────────────────────────────────┐
 │ 2. ПЛАГИНЫ (rsgi-wsrpc / plugins)    │  │ 3. ПРИЛОЖЕНИЕ (App / agrita)      │
 │    «Официальные батарейки»           │  │    «Бизнес-логика»                │
 │                                      │  │                                   │
 │ ┌──────────────────────────────────┐ │  │ ┌───────────────────────────────┐ │
 │ │ plugins.auth                     │ │  │ │ Калькуляторы удобрений        │ │
 │ │  • Модели: User, Role, Session   │ │  │ │ Дневники культур, датчики     │ │
 │ │  • Хендлеры: login.*, auth.*     │ │  │ │ Форум, статьи, чаты           │ │
 │ │  • RSA шифрование паролей        │ │  │ └───────────────┬───────────────┘ │
 │ │  • Скользящие токены (30 дней)   │ │  │                 │                 │
 │ │  • RLS (права доступа к строкам) │ │  │                 │                 │
 │ └────────────────┬─────────────────┘ │  │                 │                 │
 │                  │                   │  │                 │                 │
 │ ┌────────────────▼─────────────────┐ │  │                 │                 │
 │ │ plugins.db                       │◄┼──┼─────────────────┘                 │
 │ │  • Общий класс Base (Declarative)│ │  │  (Приложение берет `Base` и       │
 │ │  • Фабрика сессий `async_session`│ │  │  `async_session` из плагина DB!)  │
 │ │  • Пул соединений к БД           │ │  │                                   │
 │ └────────────────┬─────────────────┘ │  │                                   │
 └──────────────────┼───────────────────┘  └───────────────────────────────────┘
                    │
                    │ Выполняет SQL-запросы через SQLAlchemy
                    ▼
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ 4. БАЗА ДАННЫХ (PostgreSQL / SQLite) — «Хранилище фактов»                   │
 │                                                                             │
 │  • Таблицы авторизации (от плагина):                                        │
 │      auth_user, auth_roles, auth_tokens, active_sessions                     │
 │  • Таблицы предметной области (от приложения):                              │
 │      cult_diaries, calc_fertilizers, forum_topics                           │
 │                                                                             │
 │  *Внимание:* Внешние ключи (ForeignKey) из таблиц приложения                │
 │  ссылаются прямо на `auth_user.id` без каких-либо костылей!                 │
 └─────────────────────────────────────────────────────────────────────────────┘
```

## 2. Аналогия из жизни: Автомобиль

Чтобы легче запомнить разделение обязанностей, сравним систему с автомобилем:

| Уровень | В нашем коде | В автомобиле | Назначение |
| :--- | :--- | :--- | :--- |
| **Ядро** | `rsgi-wsrpc/core` | **Шасси, трансмиссия и проводка** | Базовая платформа. Отвечает за передачу сигналов, сокеты и протокол. Ей не важно, кто сидит за рулем и какой груз везут. |
| **Плагины** | `plugins/auth`<br>`plugins/db` | **Замок зажигания, сигнализация и бензобак** | Стандартные готовые блоки («батарейки»). Замок проверяет ключ водителя (`auth`), бензобак качает топливо (`db`). |
| **Приложение**| `App/agrita` | **Кузов и спецоборудование** | Превращает шасси в конкретную машину: трактор для агронома, спорткар или грузовик. Вся специфика проекта живёт здесь. |
| **База данных**| PostgreSQL | **Гараж и склад запчастей** | Физическое место постоянного хранения данных. |

## 3. Пошаговый сценарий запроса

Разберём, что происходит, когда пользователь нажимает в интерфейсе кнопку **«Войти»**:

```text
1. БРАУЗЕР (Клиент)
   Отправляет по открытому веб-сокету WSRPC-сообщение:
   --> {"jsonrpc": "2.0", "method": "login.submit", "params": {"username": "alex", "password": "123"}, "id": 1}

2. ЯДРО (core)
   - Принимает пакет данных из сокета через RSGI.
   - Декодирует JSON-RPC.
   - Смотрит в свою внутреннюю карту хендлеров: кто зарегистрировал метод "login.submit"?
   - Находит функцию `handle_login`, зарегистрированную через декоратор `@rpc_method("login.submit")`.
   - Вызывает эту функцию.

3. ПЛАГИН АВТОРИЗАЦИИ (plugins.auth)
   - Открывает сессию базы данных через соседний плагин:
     `async with plugins.db.async_session() as db:`
   - Выполняет запрос к таблице пользователей:
     `SELECT * FROM auth_user WHERE login = 'alex'`
   - Проверяет хэш пароля (PBKDF2-SHA256).
   - Выпускает RefreshToken со скользящим сроком (30 дней из YAML `session_lifetime_days`).
   - Запоминает контекст: привязывает к текущему сокету профиль пользователя, его роли и разрешения.
   - Возвращает результат работы ядру.

4. ЯДРО (core)
   - Упаковывает ответ в стандартный формат JSON-RPC:
     <-- {"jsonrpc": "2.0", "result": {"token": "xyz...", "role": "admin"}, "id": 1}
   - Отправляет ответ по сокету клиенту.

5. ДАЛЬНЕЙШАЯ РАБОТА ПРИЛОЖЕНИЯ (App/agrita)
   Когда этот же пользователь запрашивает расчет удобрений:
   --> {"jsonrpc": "2.0", "method": "calc.solve", "params": {...}, "id": 2}
   - Ядро перенаправляет запрос в прикладной модуль `App/agrita/backend/app/calculator`.
   - Модуль калькулятора запрашивает: «Кто сейчас вызывает метод?»
   - Из контекста сразу возвращаются данные пользователя `alex` и его права доступа!
   - Приложению больше не нужно писать код проверки сессий или логина вручную.
```

## 4. Почему база данных не разделяется на части?

Частый вопрос: *«Если плагины и приложение разделены, у них разные базы данных?»*

**Ответ: Нет, база данных одна, и это главное преимущество!**
* Плагин `plugins.db` объявляет единый декларативный класс:
  ```python
  class Base(AsyncAttrs, DeclarativeBase):
      pass
  ```
* Таблицы плагина авторизации наследуются от этого `Base`:
  ```python
  class User(Base):
      __tablename__ = "auth_user"
  ```
* Таблицы приложения Agrita наследуются от этого же `Base`:
  ```python
  from plugins.db import Base

  class CultDiary(Base):
      __tablename__ = "cult_diaries"
      user_id = Column(Integer, ForeignKey("auth_user.id"))  # Связь работает идеально!
  ```
Благодаря этому SQLAlchemy знает обо всех связях, а внешние ключи (Foreign Keys) и каскадные удаления работают без ограничений.

## 5. Как настраивать плагины из приложения (Code-First)

Фреймворк следует принципу **«Один очевидный способ без лишнего шума»**: все настройки ядра и плагинов собираются в **единой точке входа** — конструкторе приложения `app = RsgiWsrpcApp(...)`.

Никаких разрозненных вызовов `configure()` и «слепых» словарей без автодополнения:

```python
import os
from rsgi_wsrpc import RsgiWsrpcApp, VkOAuth, YandexOAuth

app = RsgiWsrpcApp(
    # --- 1. СЕТЬ, HTTP И СТАТИКА ---
    static_dir="./public",             # Папка фронтенда (Rust Zero-Copy proto.response_file)
    index_file="index.html",           # Корневой SPA-файл на GET /
    cors=True,                         # Автоматическая обработка OPTIONS и CORS
    cors_origins="*",                  # Разрешенные origins

    # --- 2. БАЗА ДАННЫХ (plugins.db) ---
    database_url=os.getenv("DATABASE_URL", "sqlite+aiosqlite:///app.db"),
    db_echo=False,                     # SQL-логирование (True для отладки)

    # --- 3. АВТОРИЗАЦИЯ И СЕССИИ (plugins.auth) ---
    secret_key=os.getenv("SECRET_KEY", "dev-secret-key-change-in-production"),
    login_rpc="login.",                # Методы, открытые гостям (вместе с is_public в БД)
    token_expire_hours=24 * 30,        # Срок жизни сессии (30 дней)
    auth_timeout=0,                    # Таймаут на вход (0 = гости не отключаются)

    # --- 4. ВНЕШНЯЯ АВТОРИЗАЦИЯ (OAuth) ---
    # Строгие типизированные классы с автоподстановкой в IDE:
    oauth=[
        VkOAuth(client_id="12345", client_secret="секрет_vk"),
        YandexOAuth(client_id="67890", client_secret="секрет_ya"),
    ],

    # --- 5. ФАЙЛОВОЕ ХРАНИЛИЩЕ (plugins.files) ---
    files_path="./uploads",            # Каталог для двухфазных загрузок (2PC Commit)
    max_upload_size=50 * 1024 * 1024,  # Лимит на размер файла (50 МБ)

    # --- 6. SEO И ДИНАМИЧЕСКИЙ РЕНДЕРИНГ (plugins.seo) ---
    enable_seo=False,                  # SSR-перехват поисковых краулеров
    sitemap_host="https://my-app.com", # Хост для генерации /sitemap.xml
)
```

### Справочник параметров `RsgiWsrpcApp`:

| Параметр | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `static_dir` | `str \| None` | `None` | Путь к папке со статикой (раздается нативно через Rust Zero-Copy). |
| `index_file` | `str \| None` | `"index.html"` | Имя индексного файла, отдаваемого на корневой `GET /`. |
| `cors` | `bool` | `True` | Включение CORS-заголовков и preflight-ответов `OPTIONS`. |
| `cors_origins` | `str \| list[str]`| `"*"` | Разрешенные домены/источники для CORS. |
| `max_message_size` | `int` | `10 * 1024 * 1024` | Максимальный размер входящего WebSocket-сообщения (10 МБ). |
| `database_url` | `str` | `"sqlite+aiosqlite:///app.db"` | URL подключения SQLAlchemy (Postgres, SQLite, MySQL). |
| `db_echo` | `bool` | `False` | Логирование выполняемых SQL-запросов в терминал. |
| `secret_key` | `str` | `"dev-secret-key..."` | Секретный ключ для подписи токенов и сессий. |
| `login_rpc` | `str` | `"login."` | Префикс публичных методов авторизации для гостей. |
| `token_expire_hours`| `int` | `720` (30 дней) | Срок действия сессионного токена. |
| `password_iterations`| `int` | `600_000` | Число итераций PBKDF2-SHA256 (стандарт OWASP). |
| `auth_timeout` | `int` | `0` | Секунды на авторизацию после подключения (`0` = отключено). |
| `guest_idle_timeout`| `int` | `900` (15 мин) | Таймаут неактивности для гостевых сокетов. |
| `user_idle_timeout` | `int` | `3600` (1 час) | Таймаут неактивности для авторизованных пользователей. |
| `oauth` | `list` | `[]` | Список типизированных провайдеров (`VkOAuth`, `YandexOAuth`). |
| `files_path` | `str` | `"./uploads"` | Папка постоянного хранения загруженных файлов. |
| `max_upload_size` | `int` | `50 * 1024 * 1024` | Максимальный объем загружаемого файла (50 МБ). |
| `backplane_url` | `str \| None` | `None` | Брокер для масштабирования (`redis://...`) при `workers > 1`. |
| `enable_seo` | `bool` | `False` | Авто-определение поисковых ботов и отдача SSR HTML. |
| `sitemap_host` | `str \| None` | `None` | Домен для генерации карты сайта `/sitemap.xml`. |

Все параметры имеют безопасные значения по умолчанию: вы указываете только то, что хотите переопределить.

## 6. Резюме архитектурных слоёв

```text
 1. ЯДРО (core/)          — Протокол, сокеты, вызов методов. Не зависит ни от чего.
 2. ПЛАГИНЫ (plugins/)    — Готовые кирпичики: DB, Auth, Files, Cache. Зависят только от ядра.
 3. ПРИЛОЖЕНИЕ (App/)     — Бизнес-логика продукта (Agrita). Зависит от ядра и плагинов.
```
