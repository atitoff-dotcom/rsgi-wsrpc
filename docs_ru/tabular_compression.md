# 📊 Табличное сжатие полезной нагрузки (RFC 0002)

Детерминированная сериализация коллекций данных для фреймворка `rsgi-wsrpc` (`app/system/tabular.py` + `wsrpc.ts`).

> **"Схема полей должна описываться один раз в контракте, а не дублироваться тысячи раз в сетевых пакетах. Табличное сжатие устраняет избыточность словарей, экономит 50–70% трафика и разгружает сборщик мусора Python."**

## 1. Концепция и преимущества

Когда веб-приложение запрашивает списки сущностей (темы форума, товары каталога, строки таблиц, справочники, списки пользователей), классический JSON сериализует каждую запись в виде изолированного словаря пар «ключ-значение»:

```json
[
  {"id": "1", "title": "Тема A", "views": 42},
  {"id": "2", "title": "Тема B", "views": 10}
]
```

### Почему это снижает производительность:
1. **Нагрузка на сборщик мусора (GC)**: Создание 1 000 словарей на каждый запрос приводит к лишним аллокациям памяти и паузам GC в Python.
2. **Неэффективность сетевого канала**: Более 50% объема JSON-пакета составляют повторяющиеся строковые ключи (`"id"`, `"title"`, `"views"`).
3. **Затраты на сериализацию**: Сериализатор JSON вынужден обрабатывать ключи для каждого элемента отдельно.

### Решение:
Табличное сжатие разделяет схему данных и их значения:
* Названия колонок объявляются **один раз** в массиве `"fields"`.
* Значения записей передаются матрицей строк в массиве `"rows"`.
* Сетевой транспорт фронтенда автоматически разворачивает строки обратно в объекты.

## 2. Формат передачи ($tabular: true)

```json
{
  "$tabular": true,
  "fields": ["id", "title", "views"],
  "rows": [
    ["1", "Тема A", 42],
    ["2", "Тема B", 10]
  ]
}
```

* **`$tabular`**: Сигнатурный флаг (`boolean`).
* **`fields`**: Упорядоченный список названий свойств (`string[]`).
* **`rows`**: Массив массивов со значениями колонок (`any[][]`).

## 3. Использование на бэкенде (Python)

Все хелперы находятся в модуле `app.system.tabular`:

### `pack_tabular`
```python
from app.system.tabular import pack_tabular

@rpc_method("forum.get_topics")
async def get_topics(session, params):
    topics = await fetch_topics()
    return pack_tabular(topics)
```

### Оптимизация сырых SQL-кортежей (ноль словарей)
Для полного исключения аллокации промежуточных словарей передавайте кортежи из курсора БД напрямую:
```python
@rpc_method("logs.get_recent")
async def get_recent_logs(session, params):
    async with db.execute("SELECT id, level, message, timestamp FROM logs") as cursor:
        rows = await cursor.fetchall()  # Список сырых кортежей
        return pack_tabular(rows, fields=["id", "level", "message", "timestamp"])
```

### Декоратор `@tabular_response`
```python
from app.system.tabular import tabular_response

@rpc_method("admin.list_users")
@tabular_response()
async def list_users(session, params):
    return await query_users()
```

## 4. Прозрачность на фронтенде (TypeScript / wsrpc.ts)

Сетевой транспорт автоматически распаковывает полезную нагрузку `$tabular` при получении:
* Корневые результаты RPC-вызовов
* Чанки мультиретурна (`stream: true`)
* Серверные push-нотификации
* Вложенные списки внутри сложных объектов

Разработчики интерфейса работают с обычными объектами:
```typescript
const topics = await wsrpc.call('forum.get_topics');
topics.forEach(t => console.log(t.title, t.views));
```

## 5. Правила проекта и стандарты

1. **Обязательно для всех коллекций**: Если метод может вернуть $>1$ записи, ответ **СТРОГО ОБЯЗАТЕЛЬНО** должен отдаваться в формате `$tabular: true`.
2. **Прозрачность UI**: В компонентах интерфейса запрещено работать со строками по индексам колонок вручную — распаковка выполняется в сетевом слое.
3. **Совместимость тестов**: Тестовый клиент прозрачно разворачивает табличные структуры по умолчанию (`raw=False`), позволяя выполнять строгую проверку формата через `raw=True`.
