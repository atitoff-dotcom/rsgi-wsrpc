## 1. Фундаментальная концепция и разделение прав

В системе устанавливается строгое архитектурное разделение двух видов прав:

```
                     ┌──────────────────────────────────────────────┐
                     │         Входной реестр всех прав             │
                     └──────────────────────┬───────────────────────┘
                                            │
                     ┌──────────────────────┴───────────────────────┐
                     ▼                                              ▼
     ┌───────────────────────────────┐              ┌───────────────────────────────┐
     │      1. Права на ДАННЫЕ       │              │     2. Права на ЗАПУСК        │
     │            (CRUD)             │              │            (RPC)              │
     ├───────────────────────────────┤              ├───────────────────────────────┤
     │ • Привязано к моделям         │              │ • Привязано к процедурам      │
     │   SQLAlchemy (ModelRegistry)  │              │   и сервисному коду           │
     │ • Гранулярность:              │              │ • Гранулярность:              │
     │   C, R, U, D                  │              │   Строго булево (Да / Нет)    │
     │ • Контекст:                   │              │ • Контекст:                   │
     │   Свои (Row-level) / Все      │              │   Только факт вызова          │
     │ • Примеры:                    │              │ • Примеры:                    │
     │   Task, Article, Order        │              │   as.update, reports.export,  │
     │                               │              │   system.reboot, ai.generate  │
     └───────────────────────────────┘              └───────────────────────────────┘
```

### Ключевые правила:
1. **Zero Trust / Default Deny:** По умолчанию любому пользователю закрыт доступ ко всем моделям и ко всем RPC (кроме публичных эндпоинтов вроде `login.*`).
2. **Роль `ADMIN` исключена из таблицы:** У администратора (`is_superadmin`) безусловный полный доступ ко всему. В интерфейсе настройки прав роль `admin` не отображается.
3. **Роль `User` обязательна:** Это базовый уровень прав любого зарегистрированного пользователя. По умолчанию ей всё запрещено в CRUD. Администратор явно выдает минимальный набор прав.
4. **Гибридный доступ (Роли + Персональные права):**
   * Разрешения могут назначаться роли.
   * Разрешения могут назначаться **персонально конкретному пользователю** (действуют как индивидуальная надбавка поверх ролей без необходимости создавать уникальную роль под одного человека).
5. **Авто-интроспекция от SQLAlchemy при старте:**
   * Все сущности БД берутся из `ModelRegistry` / `Base.metadata`.
   * Если метод — это системный вызов CRUD (`crud.*`) или ассоциирован с моделью, к нему применяются права CRUD.
   * Если метод — это произвольный код (`as.update`, `reports.export`), к нему применяется **только булево право на запуск (Да / Нет)**.

## 2. Структура экранов интерфейса (GUI)

### Экран 1: Таблица «Пользователи»
Отображает список всех пользователей системы.
* **Колонки:**
  1. `Login` — логин пользователя.
  2. `E-mail` — адрес электронной почты.
  3. `Роли` — бейджи назначенных ролей (мультиселект/инлайн-редактирование).
  4. `Разрешения` — сводный индикатор (например: `12 прав`, при наличии персональных прав — бейдж `+Персональные`) + кнопка открытия модального окна.

### Экран 2: Таблица «Роли»
Отображает список ролей системы (исключая системную роль `admin`).
* **Колонки:**
  1. `Роль (пользователей)` — название роли и счетчик привязанных к ней пользователей: `User (42)`, `Менеджер (15)`, `Бухгалтер (3)`.
  2. `Разрешения` — сводный индикатор настроенных прав + кнопка открытия модального окна.

## 3. Модальное окно «Разрешения» (`PermissionsModal.svelte`)

Универсальный компонент по центру экрана, открывающийся как для **Роли**, так и для **Пользователя**.

### Каркас окна:
* **Заголовок:** `Разрешения: Роль «User»` либо `Разрешения: Пользователь «alex» (alex@example.com)`.
* **Переключатель вкладок (Tabs):**
  1. `📦 Модели данных (CRUD)`
  2. `⚡ Вызовы процедур (RPC)`
* **Подвал (Footer):** Кнопка `Отмена` и акцентная кнопка `Сохранить изменения`.

### Вкладка 1: «Модели данных (CRUD)»
* **Инструменты:** Поиск модели по названию, кнопки пресетов: `«Только чтение»`, `«Сбросить всё»`.
* **Матрица прав:**
  | Модель | Создание (C) | Чтение (R) | Изменение (U) | Удаление (D) | Область действия |
  | :--- | :---: | :---: | :---: | :---: | :--- |
  | **Task** | `[✓]` | `[✓]` | `[✓]` | `[ ]` | `[ Только свои (Row-level) ▼ ]` |
  | **Article** | `[ ]` | `[✓]` | `[ ]` | `[ ]` | `[ Все записи (Global) ▼ ]` |
* **Логика строк:**
  * `Create` — чисто булево (Да / Нет).
  * `Read`, `Update`, `Delete` — чекбоксы + селект области: `Только свои (Row-level)` / `Все записи (Global)`.
  * При открытии для пользователя: права, пришедшие из назначенных ролей, визуально отображаются с иконкой замочка `🔒 (из роли Менеджер)`. Персональные права подсвечиваются как активные переопределения.

### Вкладка 2: «Вызовы процедур (RPC)»
* **Инструменты:** Быстрый поиск метода по строке.
* **Группировка по доменам/префиксам:**
  * Группа с маской `*`: чекбокс `tasks.*` покрывает все методы группы.
  * Аккордеон со списком конкретных процедур (`as.update`, `system.reboot`, `billing.charge`).
  * Для каждого метода — простое булево: `[✓] Разрешено` / `[ ] Запрещено`.

## 4. Бэкенд и Модели данных (`rsgi_wsrpc`)

### 4.1. Хранение прав в БД
1. **Права для ролей:**
   * Уже существуют: `RolePermission` (`auth_role_permission`) и `RoleRpcPermission` (`auth_role_auth_rpc_permission`).
2. **Персональные права для пользователей:**
   * Добавить поддержку моделей:
     * `UserPermission` (`auth_user_permission`): `user_id`, `model_name`, `can_create`, `can_read`, `can_update`, `can_delete`, `row_level_only`.
     * `UserRpcPermission` (`auth_user_auth_rpc_permission`): `user_id`, `rpc_permission_id`.
3. **Вычисление прав:**
   * Метод `User.get_permissions()` и `User.get_allowed_rpc_methods()` объединяет:
     $$\text{Итоговые права} = \bigcup (\text{Права ролей}) \cup (\text{Персональные права юзера})$$

### 4.2. WSRPC API методы для интерфейса
* `permissions.get_schema` — возвращает полный список зарегистрированных моделей и список доступных RPC-методов.
* `permissions.get` (`target_type="role"|"user"`, `target_id=...`) — возвращает текущее состояние прав сущности (с флагами унаследованных прав).
* `permissions.save` (`target_type`, `target_id`, `crud_permissions`, `rpc_permissions`) — атомарно сохраняет настройки прав и инвалидирует кэш сессий.
